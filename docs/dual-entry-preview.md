# DSH-company 双入口验收预览 / Dual-entry preview

版本：`0.7.0-dual-preview.1`。这是基于公开 v0.6.0 的独立开发预览，不是此前的 0.7.0 RC，也没有发布到 npm 或 GitHub。建议在新 Harness Web 配置目录验收，不要覆盖日常配置。需要已安装的 DSH Harness（`dsh` 命令）、默认 JSON 存储组件和已配置模型。模型执行可能产生费用。

## 验收操作（约 5 分钟）

1. 进入 **AI 公司**。输入“为 dsh-company 拟一份开源发布前检查清单，只写文字，不发帖、不发布”，再填验收标准“包含版本、安装、测试和回滚四项”。点**生成待审批方案**。应看到**精简方案**及**证据优先方案**，每项有路径、风险、可行性和负责人。该预览为规则草案，不是模型实时调研。
2. 选**证据优先方案**，点**批准所选方案与版本**。应显示已批准且尚未运行；直到手动点**开始已批准的运行**，才会调用模型。需求和技术节点并行，后续执行、测试和审核有依赖，不再广播抢单。
3. 观察逐节点状态和输出。审核人须明确给出 PASS；失败可显式重试同版，最多五次运行尝试。重试为重跑全图，不是节点级续跑。真实模型可能拒绝验收，不保证最终 PASS。
4. 完成后点**保存成功方案为固定流程**，进入原有画布。它只复制流程结构，不复制首次输入、审批或结果。填入新任务运行；受保护模板保留独立审核。也可从首页**固定流程**入口直接创建普通工作流，无需经过公司审批。
5. 刷新、或停止后重新启动同一隔离配置。已完成、失败的方案和模板应仍在；运行中被打断的记录应标为失败，且不会自动续跑。

### 在隔离配置中安装

解压验收包至普通目录，终端切到它所在目录后运行。命令中的包路径只引用解压后的文件。

```sh
DSH_HOME="$HOME/.dsh-dual-preview" dsh plugin --profile web add "$PWD/dsh-company-0.7.0-dual-preview.1.tgz"
DSH_HOME="$HOME/.dsh-dual-preview" dsh web --host 127.0.0.1 --port 13081
```

使用终端显示的本机登录链接，点击 DSH-company 面板。全新的配置不会自动带入日常模型授权，不要把 API 密钥贴到聊天中。若只要浏览不调用模型，生成方案后停在批准界面即可。

## 本预览的边界

- 公司入口与固定工作流共用同一个执行器；计划快照与普通画布在界面上区分。旧任务板仍保留，不改变其历史语义。
- 新公司运行与其另存模板使用新员工会话、不注入旧员工记忆，不向员工授予原员工全局工具。输入可能发给所配置模型，避免在验收样例输入敏感材料。不是操作系统沙箱。
- 审批范围是本机 Harness 已认证的配置，**不等于**已经接入多用户权限或逐项目隔离。技术总监做文字选型；本轮没有连通本地 Skills/MCP 盘点、在线 GitHub 查证或真实文件操作。
- 模型的审核结论是文本判断。模拟模型验收证明调度、状态和阻断，不证明模型实际交付一定合格，也不代表 CPA 真机验证。
- 如处于专门隔离配置而仍遇到安装问题，先保留原配置不动。不要用预览包覆盖发布候选包。

## 10 轮改进记录

| 轮次 | 改进 | 校验重点 |
|---|---|---|
| 1 | 应用内两种入口，保留旧任务板 | 入口和固定画布导航 |
| 2 | 职责确定的两套方案 | 两张实际不同的依赖图，具备独立岗 |
| 3 | 明示风险、可行性和自定义验收 | 双语字段、验收标准随审批版本记录 |
| 4 | 审批与执行分开 | 旧版本、错选项、未审批和重复请求拒绝 |
| 5 | 共用原执行器，锁定公司运行快照 | 判断分支并行及阻断对快照的直接编辑和运行 |
| 6 | 新运行会话和文字限定 | 不复用员工历史；双方不继承全局工具 |
| 7 | 独立测试、审核和升级模板门槛 | 明确 PASS 才可另存，FAIL 不可绕过 |
| 8 | 实时状态与可恢复交互 | 状态、输出、取消、明示整图重试；旧宿主语言包回退 |
| 9 | 实际宿主发现并修复存储竞态 | 启动依赖、串行落盘和重启后的状态 |
| 10 | 包完整性和验收说明 | 精确安装内容、自动化回归、交付验收入口 |
