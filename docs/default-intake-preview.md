# Company intake preview

The default company intake in the company panel creates a deterministic, model-free proposal. It repeats the goal, expected outcome, boundaries and concrete checks for owner review. It offers the lean sequential plan by default; the alternative parallel requirements/research path is an explicit tradeoff opt-in. A generic default outcome is not a tailored analysis and model-based planning is not part of this preview.

Approve only the current revision and explicit option, then choose Start. Editing or rejection clears approval; even returning to the original text produces a fresh revision. A repeated start does not dispatch another run. After a failed or cancelled attempt, an explicit retry identifies the last observed attempt. Technical selection is routed to the existing technology lead after approval, within the approved scope; independent QA and review remain separate stages. New intake turns are report/text only, require the host's tool execution guard, and never grant filesystem or publication capabilities. A FAIL or absent exact PASS on review blocks successful completion and promotion. This is not semantic enforcement of a human instruction nor proof that tools ran.

Existing saved company drafts retain their original fingerprints, old fixed workflows retain their explicit direct-run path, and historical storage tables and versions are unchanged. Separate legacy missions and slash/agent-tool dispatch are not migrated, and neither groups nor the quant preview are altered. The gate uses the pinned Harness exact-route owner-peer boundary, not a new project ACL or defense against a trusted owner automation. Existing workflows, groups and app versions were not upgraded or installed for this check. The integration tests simulate the supported route, durable records and agent events without model or provider requests.
