# 量化作战室预览：只读日志接入

本轮把 DSH-company 的执行工作台、可持久群聊、固定模板快捷运行和量化作战室放进同一个独立预览。不是 npm 正式发布，不连接券商，不发邮件。岗位状态表示原 TradingAgents 的记录映射，不声称每个已有岗位里正在开一个独立 AI 模型。群聊消息来自选定员工的独立 Harness 回复；它不是独立的项目文件安全边界。

## 打开方式

在隔离 Harness 中安装本地 TGZ，打开「公司 → 量化作战室」。未配置时五岗应显示未知。通过**测试配置**可指向已核实的 TradingAgents data 本地目录：

```yaml
- id: dsh-company
  config:
    quantMode: replay
    quantReplayDate: '20261119'
    quantLegacyTimezone: Asia/Shanghai   # Only after verifying the source produces local time
    quantLogRoot: /替换成现有本机选择的TradingAgents/data
```

可显式使用 paper 或 live_readonly；live_readonly 仅代表读取现有日志，不证明行情供应实时、覆盖充分或脚本在持续运行。API 每次投影三类白名单日志的有界记录，浏览器不会获得股票、持仓、邮件正文或地址。代码不启动旧守护进程。旧版无时区的审核和投递日志仅在显式配置已核验源时区时解释为本地时间。若缺结构化卖出数据或最新行情时间，应一直显示未验证，不能把日志时钟当行情时钟。

## 按原会话落地的检查顺序

1. 行情质检：交易日、时戳、末笔与带日期报价一致性未证实时，不能进入通知。从现有日志仅显示可证实的覆盖与异常计数。
2. 情绪和题材：板块、资金、热榜、龙虎榜、新闻与催化有据时才采用。未对接即显示未知。
3. 盘口扫描：冲板、内切、趋势龙头、外切、低吸分别记录候选及进入评估的数量；观察留在工作台。历史 7%–9% 是原规则候选范围，不是无差别的买入条件。
4. 风控和审核：审核结果与耗时单列；卖出前需取得可信的可卖数量与标记日期。回放禁止未来数据，不以未出邮件等同继续持有。
5. 通知：午休、观察、未确认、证据不足及重复告警一律不通过；即使通过也只是预览 dry-run。已有 SMTP 受理回执与本预览实际发送区分。不得向原对话提到的其他人发送，除非当前授权明确。

交易时钟预览以沪深竞价市场的连续竞价窗为参考；它不替代交易日历，竞价、节假日与停牌边界必须以外部确认的当日市场状态为准。 [上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml) / [深交所市场概览](https://www.szse.cn/English/services/trading/tradOverview/)。

## 策略评测而非收益承诺

候选模块的变化先做固定窗口回放，再做滚动样本外、费用与滑点校正、信号命中与漏检归因、最大回撤及模拟盘；只有验收和复核后才替换版本。缺 minute bar 或有前视偏差的历史回放不得作为基准。用逐条记录判断每个员工是否完成了其职责，不以单次收益或短视频自述验收。
